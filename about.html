01 — What it does

무엇을 하는 도구인가

기억에 의존하면 세 번째 방부터 앞의 방이 흐려집니다. 그래서 그 자리에서 기록하고, 규칙으로 점수를 매깁니다.

📝 현장 체크리스트

방향·채광·수압·콘센트·곰팡이·누수·벌레·엘리베이터·중문·주차 등을 방에서 나오기 전에 입력합니다.

📊 비교 대시보드

보증금·월세·도보시간·점수·방문일·부동산·평가 상태로 필터링. 상세 모달에서 이전/다음 방을 바로 넘겨 비교합니다.

🖼 사진 관리

구글 드라이브 폴더의 사진을 골라 붙입니다. 다른 방이 이미 쓴 사진은 “사용 중”으로 표시돼 중복 선택이 막힙니다.

📚 지식 탭 4종

계약 전 안전장치 · 현장 점검 노하우 · 추천 특약사항 · 생활 편의 체크. Gemini와 설계해 코드로 고정했습니다.

⚡ 점수는 이렇게 계산됩니다 — 기본 50점에서 가점·감점, 0~100으로 클램프

02 — Architecture

서버도 빌드도 없는 3층 구조

정적 HTML 한 장이 Apps Script 웹앱 URL 하나와 통신합니다. DB 자리에는 구글 시트가, 이미지 스토리지 자리에는 드라이브 폴더가 들어갑니다.

03 — Authentication

비밀번호는 왜 서버로 옮겨졌나

처음에는 const EDIT_PASSWORD = "…" 가 HTML 안에 있었습니다. 브라우저가 읽어야 하는 값은 사용자도 읽습니다 — 클라이언트에 비밀은 존재할 수 없습니다.

등록 · 수정 · 삭제 요청의 생애

🚫 왜 프론트엔드로는 안 되나

난독화·Base64·해시로 바꿔도 소용없습니다. 브라우저가 실행해야 하는 코드는 사용자가 전부 읽을 수 있습니다. 더구나 초기 버전은 저장 요청에 비밀번호를 아예 싣지 않아서, 검사가 사실상 장식이었습니다.

✅ 두 겹으로 막습니다

1차 — 모달의 verify: 잘못된 비밀번호로는 폼이 열리지 않습니다.
2차 — 저장·삭제 요청의 isAuthorized(): 개발자도구로 1차를 우회해도 여기서 걸립니다. 진짜 방어선은 2차 하나이고, 1차는 UX를 위한 편의입니다.

⚠️ 그래도 남는 한계

  • 조회는 완전 공개 — URL을 아는 사람은 시트 내용을 봅니다
  • 공용 비밀번호 하나 — 개인별 인증이 아닙니다
  • 가족·친구끼리 쓰는 수준이며, 민감한 데이터에는 부적절합니다
04 — Agent workflow

서브에이전트와 스킬로 일하는 방식

메인 에이전트가 요청을 분해하고, 서브에이전트가 병렬로 조사하고, 스킬이 정해진 절차를 대신합니다. 결과는 추측이 아니라 실제 요청을 보내 확인합니다.

역할 분담

실제로 이렇게 흘러갔습니다

  1. 1
    요청 해석 — “하드코딩된 비밀번호를 감춰라”를 클라이언트에 비밀은 존재할 수 없다는 제약으로 재정의
  2. 2
    병렬 조사 — Explore 가 레포 구조를, Plan 이 인증 설계를 동시에 수행
  3. 3
    스킬 호출 — 스킬이 시각화·문서 작성·브라우저 자동화를 정해진 절차대로 처리
  4. 4
    구현 — 검증을 서버로 이전 · filter-repo 로 깃 히스토리에서 비밀번호 제거 · 서비스 종료된 외부 이미지 의존 제거
  5. 5
    실측 검증 — 추측 대신 실제 배포본에 요청을 보내 응답 확인. 자기 자신 안에 중첩된 doPost를 이 단계에서 발견했습니다 — 함수가 아무것도 반환하지 못해 모든 쓰기가 무인증으로 통과하던 상태였습니다
  6. 6
    배포와 재검증 — git push → Vercel 자동 반영. 결과가 기대와 다르면 1번으로 되돌아갑니다

💡 이 과정에서 배운 것

같은 증상(Failed to fetch)에 원인이 셋 겹쳐 있었습니다 — 중첩된 함수, 배포 액세스 권한, 갱신되지 않은 배포. 추측을 멈추고 실제 요청을 보내 응답을 읽는 것만이 이를 갈라냈습니다.

05 — Ship it

배포와 운영

빌드 산출물이 없으니 배포는 파일을 올리는 일에 가깝습니다. 다만 백엔드에는 한 가지 함정이 있습니다.

두 개의 배포 경로 — 이 둘은 완전히 별개입니다

🚀 처음 배포하기

1. vercel.com/new 에서 레포 Import
2. Framework Preset: Other
3. Deploy

설정 파일도 빌드 명령도 필요 없습니다. 이후 main 에 푸시하면 자동으로 재배포됩니다.

⚙️ Apps Script 세팅

1. 시트 → 확장 프로그램 → Apps Script
2. apps-script-Code.gs 붙여넣기
3. 스크립트 속성에 EDIT_PASSWORD 추가
4. 배포 → 웹 앱, 액세스 모든 사용자
5. 발급된 URL 을 WEB_APP_URL 에

🧯 막히면 여기부터

Failed to fetch → 스크립트가 JSON 을 못 돌려준 상태. 오류 페이지에는 CORS 헤더가 없어 브라우저가 원인을 읽지 못합니다.

액세스 권한이 “Google 계정이 있는 모든 사용자”면 익명 요청이 로그인으로 튕깁니다. “모든 사용자”여야 합니다.

재배포를 했는지 다시 확인하세요.
